Sonic Time Travelers: Can a Song’s Identity Place It in Its Era?

0. GitHub Repo:

https://github.com/phuonganhdangamy/jsc370-project

I. Introduction

The project is motivated by a cultural observation: just as fashion cycles repeat themselves, music appears to be so as well. Some artists are frequently noted for their retro aesthetics despite being comtemporary acts. There is a term in marketing called “nostalgia sells”: a strategy in marketing/creative that promotes products with characteristics that could evoke emotional feelings from customers so that they will make the purchase decision more easily.

This sparks curiosity on whether this phenomenon of having a retro is statistically measurable and whether it correlates with commercial succes, or is lyrical music timeless and doesn’t change over time?

Research Question

““Can a song’s lyrical identity reliably place it in its era, and do modern songs whose lyrics read as vintage actually sell better?”“

Hypotheses

We have some predictions regarding the outcome of our study:

Primary Hypothesis: Lyrical embeddings carry meaningful decade signal and a classifier trained on them will perform above chance, but adjacent decades, particularly the 1990s-2000s or the 2010s-2020s will be systematically confused due to shared vocabulary and thematic overlap.

Secondary Hypothesis: Modern songs from the 2010s and 2020s that are misclassified as belonging to the 1980s or 1990s will be more popular than correctly classified modern songs, supporting a “nostalgia sells” theory

Novelty

Most existing work using Spotify data relies on static Kaggle datasets and focuses on audio features alone, ignoring the lyrical dimension entirely. This project is distinctive because:

  • All data is collected live through API calls rather than downloaded as a pre-assembled dataset, giving us full control over sampling strategy and decade balance.

  • We integrate multiple data sources like Spotify for metadata, Genius for lyrics, and MusicBrainz for artist cultural context into a unified analysis.

II. Methods

Data Sources

In order to answer all aspects of the research question, we collect and combine data from different sources:

  1. Spotify Web API

  • Documentation: https://developer.spotify.com/documentation/web-api

  • Purpose: Track metadata and decade labeling

  • What we collect: track ID, track name, artist name, album ID, release date

  • Method: Search API queries by decade and genre keyword. For example, we query 80s rock tracks by calling rock year:1980-1989. Then pull the results by batches of 10. To respect Spotify’s API rate limits (~5.5k records/day), we split the data collection process into 3-4 days to account for code bugs or unexpected failures.

  1. Genius API + Web Scraping

  • Documentation: https://docs.genius.com/

  • Purpose: Song lyrics for lyrical embedding

  • What we collect: Raw lyrics for each track, scraped from Genius song pages after searching by artist name and track name via the Genius search API

  • Method: First, we query the Genius search API to find the lyrics URL. Then, we will scrape the lyrics page using BeautifulSoup. After that, the scraped lyrics are cleaned by removing section headers such as [Verse 1], non-ASCII characters, and excess whitespace using regex. Cleaning will help further steps easier.

  1. MusicBrainz API

  • Documentation: https://musicbrainz.org/doc/MusicBrainz_API

  • Purpose: Cultural enrichment and enhancing knowledge about the artists.

  • What we collect: artis country (mb_country), area of origin (mb_area), city of origin (mb_begin_area), match confidence score (mb_score) community tags, and genre tags.

  • Method: We search by artist name, then fetch the full artist record with tags. We have to put on rate limit to respect MusicBrainz policy. The artist names come from previously fetched spotify dataset, so to safe time, this collection process will run after every daily spotify collection, then append to the “master file”. Match confidence score is retained to filter low-quality matches.

Data Acquisition

Step 1: Seed Artists via Decade Playlists

Data collection begins with a playlist-seeding strategy using Spotify’s curated decade playlists as entry points. For each decade from the 1980s to the 2020s, we identified four playlists covering distinct genre branches to ensure the resulting artist pool is not dominated by a single style. Rock, Pop, and Hip Hop are sampled consistently across all five decades given their sustained cultural presence, while decade-specific genres such as Dance (1980s), RnB (1990s), Country (2000s), EDM (2010s), and Latin (2020s) are included to capture the unique sonic flavors of each era.

Step 2: MusicBrainz Enrichment

To supplement Spotify’s metadata with cultural context, we query the MusicBrainz API for each unique artist in our dataset. MusicBrainz is an open-source community-maintained music encyclopedia that provides structured data not available through Spotify, including the artist’s country of origin, the city or region they are associated with, and community-contributed genre and style tags.

For each artist, we perform a name-based search to retrieve the MusicBrainz artist ID, then make a detailed record fetch with tags and genres included. A match confidence score is returned with each search result and retained for downstream filtering. MusicBrainz enforces a strict rate limit of one request per second, which is respected using a fixed 1.1-second sleep between calls.

The resulting enrichment covers artist origin country, broader area, city of origin, and pipe-separated tag and genre strings.

Step 3: Lyrics via Genius

Lyrics are retrieved for each track in our Spotify dataset. For each track, we first query the Genius API using the cleaned artist name and track name to obtain the lyrics page URL. Then we scrpae the page content using BeautifulSoup. Track names are pre-cleaned before querying by stripping parenthetical annotations such as “(Remastered)” or “(feat. Artist)” which tend to confuse the search results.

Songs returning fewer than 20 words after cleaning are treated as failed scrapes. A checkpoint is saved every 500 tracks so the pipeline is fully resumable in the event of interruption or API failure.

Step 4: Fetch page views via Genius

This is a new step added after the initial proposal to provide a more direct measure of the “nostalgia sells” hypothesis. For each track with a successfully scraped Genius page, we will query the Genius API for the song’s page views as a proxy for popularity and listener engagement. The page views metric captures how many times the song’s Genius page has been viewed, which can reflect both the song’s popularity and the level of listener interest in its lyrics. We will analyze whether modern songs misclassified as vintage have higher page views than those correctly classified, providing evidence for or against the nostalgia sells theory.

Step 5: Lyrical Embeddings

To represent lyrics as numerical features suitable for machine learning, we use the all-MiniLM-L6-v2 model from sentence transformers library to generate dense vector embeddings of each song’s full lyric text. This model maps variable-length text to a fixed vector that captures semantic meaning, making it possible to compare songs lyrically in a continuous embedding space regardless of exactly vocabulary differences. Embeddings will be cached to file after generation to save computation time later on.

Step 6: Cleaning and Labeling

With all raw data sources collected, we perform cleaning, decade labeling, and cross-source alignment in a single consolidated step. By cleaning after all fetching is complete, we avoid discarding tracks that may have failed one pipeline but could still contribute to the analysis.

First, we clean the Spotify tracks. Release years are extracted and parsed, records outside the 1980 and 2026 range are removed, and tracks identified as remasters, live versions, or remixes via regex are filtered out. Deduplication retains only the earliest known release per artist and track name pair to preserve the song’s true era of origin. Decade labels are then assigned by binning release years into 5 categories. A stratified cap of 2000 songs per decade is applied to correct for the overrepresentation of the 2010s.

The audio features, MusicBrainz, and lyrical embeddings are merged against the cleaned Spotify track list using track id and artist id. Tracks that failed MusicBrainz matching are retained in the audio and lyrics datasets with null rather than dropped, since country of origin is a supplementary feature than required. Tracks that failed Genius scraping are excluded only from the lyrics and master datasets but remain in the audio-only.

Step 7: Feature Engineering

Final Dataset Summary

After ingestion and preparation, the master dataset contains 9,176 tracks that additionally have lyrical embeddings available, representing the intersection of the audio dataset with successfully scraped and embedded lyrics.

Before cap, the observations are not so different from each other. However, it is still fairer to do capping. The lowest is 2010s with 1854 records.

Embedding coverage (ratio between the master dataset which has lyrics embeddings vs. audio dataset) is 93.1%.

Analytical Tools

  • Data collection is handled through direct HTTP calls via the requests library to the Spotify Search API, Genius API, and MusicBrainz API, with beautifulsoup used for lyrics page scraping. Data is managed with pandas and serialized using pyarrow. Lyrical embeddings are generated with the sentence-transformers library using the all-MiniLM-L6-v2 model. Exploratory analysis uses matplotlib, seaborn, and plotly for visualization, and scikit-learn for preprocessing and dimensionality reduction.

IV. Summary & Final Project Plan

Key Findings So Far

Our preliminary analysis of the lyrical corpus reveals several meaningful patterns that both support and complicate the central research question.

On lyric length, we find a clear declining trend in mean word count from the 1980s through the 2020s, though this is driven primarily by the disappearance of long-form outliers in recent decades. Genre emerges as a stronger driver of lyric length than decade, with hip hop producing nearly double the word count of country and EDM, suggesting that the apparent temporal decline in lyric length partially reflects the changing genre composition of each decade rather than a pure shift in songwriting style.

The TF-IDF analysis reveals decade-distinguishable vocabulary after aggressive stopword removal, with the 1980s characterized by rock and dance-era themes, the 1990s by the language of hip hop authenticity, and the 2010s by a more introspective vocabulary. However, the growing representation of Spanish in the corpus requires further attention and decision regarding how to process them.

We have seen that songs cluster more strongly by genre than by decade, suggesting that a supervised classifier is necessary and motivating incorporating additional features in the final project, such as Spotify API’s audio features. (Due to technical constraints encountered during data collection (i.e., Spotify API rate limits under development mode that prevented reliable audio feature retrieval at scale), the current report is limited to lyrical features only.)

Final Project Plan

II. Data Modeling

1. Splitting the Dataset

The master dataset will be splitted into training, validation, and test sets using a stratified split to preserve decade class proportions across all three partitions. We will use a 70/15/15 train/validation/test split.

We will also stratify data by artist to prevent leakage: All songs by a given artist will be assigned to the same split, ensuring the model cannot memorize artist style rather than era characteristics.

2. Training the Models

We will use supervised machine learning model to predict decade (5 classes: 1980s, 1990s, 2000s, 2010s, 2020s). Some models we will try are:

  • Multinomial logistic regression: This will be a baseline, providing an interpretable lower bound on classification performance.

  • XGBoost classifier: We expect it to capture the non-linear interactions in the embedding space that logistic regression cannot.

For both models, PCA will be applied to reduce the 384-dimensional embeddings, balancing computational efficiency with information retention.

Models will be trained and hyperparameter tuned according to the performance on validation set.

We will additionally explore whether adding lyric_word_count, detected language, or artist country of origin as supplementary features improves decade prediction beyond embeddings alone.

3. Validation

For each model we will perform 5-fold cross-validated grid search over key hyperparameters (learning rate, max depth, number of estimators) for XGBoost, using the training set only.

Macro-averaged F1 score will serve as the primary validation metric to account for class imbalance across decades. Per-class F1 scores will also be monitored to identify which decades are most difficult to classify. Early stopping will be applied during XGBoost training to prevent overfitting on the training fold.

III. Performance Evaluation

Final evaluation will be performed once on the held-out test set after hyperparameter selection is complete. We will report macro and weighted F1, precision, and recall for both the logistic regression baseline and XGBoost model, alongside full confusion matrices to visualize systematic misclassification patterns across decades.

The confusion matrix will be the main interest to answer our research question, by looking at the off-diagonal terms. SHAP values will be computed for the XGBoost model to identify which embedding dimensions most drive decade misclassification, and UMAP projections of the test set will be colored by true decade, predicted decade, and misclassification status to provide an interpretable visual summary of model behavior.

IV. Interaction Component

The final project will be published as a website.

There will be a component called “What Era Do Your Lyrics Belong To?” tool where a user pastes any block of text or song lyrics and it returns a predicted decade with confidence scores across all five classes displayed as a bar chart.

Also, there can an interactive UMAP scatter plot of the full corpus where users can filter by true decade, predicted decade, genre, or artist country of origin, with hover tooltips showing song name, artist, true era, and predicted era. Songs that are misclassified as a different decade will be highlighted as time travelers.
